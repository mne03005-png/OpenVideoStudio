# Support

## Getting help

1. **Check `docs/INSTALL.md`'s troubleshooting section** first — most
   early setup issues (Ollama unreachable, ComfyUI path errors, VRAM
   issues) are already covered there.
2. **Search existing [Issues](../../issues) and
   [Discussions](../../discussions)** — someone may have already hit the
   same problem.
3. **Ask in [Discussions → Help](../../discussions/categories/help)** for
   usage questions, setup problems, and "is this expected behavior"
   questions.
4. **Open an [Issue](../../issues/new/choose)** for a specific,
   reproducible bug or a concrete feature request — use the relevant
   issue template.

## What belongs where

| Question type | Where |
|---|---|
| "How do I...?" / setup help | Discussions → Help |
| "I think I found a bug" | Issues (bug report template) |
| "It would be great if..." | Issues (feature request template) or Discussions → Ideas |
| "I ran it on hardware X, here's what happened" | Issues (hardware report template) — see `docs/HARDWARE.md` |
| Security vulnerability | Private Security Advisory — see `SECURITY.md`, **not** a public issue |
| "I want to contribute, where do I start?" | `CONTRIBUTING.md` + `docs/ISSUES_SEED.md` |

## Response expectations

During the first two weeks after public launch, every new issue gets at
least an acknowledgment within 24 hours (see
`docs/OPEN_SOURCE_LAUNCH_STRATEGY.md`'s first-week community plan).
Afterward, response time depends on maintainer availability — this is a
community project, not a paid support product.
